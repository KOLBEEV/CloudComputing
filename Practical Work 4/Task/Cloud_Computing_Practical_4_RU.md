# Облачные вычисления · Практическая работа № 4
## Резервное копирование и восстановление облачного сервиса

**Цель работы.** Проверить, какие записи о регистрации на курсы сохраняются при пересоздании контейнера и какие можно восстановить после потери хранилища. Измерить время восстановления и определить возраст восстановленной копии на момент сбоя.

### Задание 1. Соберите образ CourseHub

Распакуйте исходники в ВМ и откройте каталог с Dockerfile. Если базовый образ ещё не загружен, поместите в этот каталог выданный файл `python-3.12-slim.tar`. Соберите образ из исходников:

```bash
docker image inspect python:3.12-slim >/dev/null 2>&1 || docker load -i python-3.12-slim.tar
docker build --pull=false --network=none -t coursehub-pz3:1 .
docker image inspect coursehub-pz3:1 --format '{{.Id}} {{.Architecture}}'
```

Сохраните вывод последней команды. Кратко объясните, что делают инструкции `FROM`, `WORKDIR`, `COPY` и `CMD`.

### Задание 2. Пересоздайте контейнер

1. Запустите CourseHub. Зафиксируйте идентификатор контейнера и имя подключённого тома.
2. Через API создайте две записи на курс **CC101** для условных студентов **A** и **B**. Сохраните ответ API со списком из двух записей.
3. Пересоздайте контейнер с тем же томом. Зафиксируйте новый идентификатор контейнера и убедитесь, что имя тома осталось прежним.
4. Снова запросите список регистраций. Проверьте, сохранились ли записи A и B.

### Задание 3. Создайте резервную копию и добавьте ещё одну запись

1. Создайте согласованную копию базы SQLite с помощью команды резервного копирования из сценария. Зафиксируйте путь к файлу и время создания снимка `t_backup`. Приостановите запись данных на время копирования, чтобы однозначно определить момент, которому соответствует состояние базы.
2. Убедитесь, что копия находится вне тома Docker. Зафиксируйте её размер, контрольную сумму SHA-256 и результат проверки целостности SQLite.
3. После создания копии добавьте запись на курс **CC101** для студента **C**. Зафиксируйте время её создания и сохраните ответ API со всеми тремя записями.

### Задание 4. Имитируйте потерю хранилища

1. Зафиксируйте время сбоя `t_failure` непосредственно перед остановкой CourseHub. Для всех отметок времени используйте часы ВМ и один часовой пояс.
2. Удалите учебный контейнер и выделенный для него том с помощью команды из сценария. Убедитесь, что том удалён, а файл резервной копии по-прежнему доступен.
3. Запустите CourseHub с новым пустым томом. Запросите список регистраций и сохраните HTTP-статус и тело ответа. Успешный ответ с пустым списком подтверждает, что API доступен, а исходные записи отсутствуют.

### Задание 5. Восстановите базу и проверьте результат

1. Остановите сервис, восстановите базу SQLite из резервной копии в новый том и снова запустите CourseHub.
2. Запросите список регистраций. Убедитесь, что **записи A и B восстановились, а запись C отсутствует**. Зафиксируйте время `t_recovered` сразу после первого ответа API, подтвердившего восстановление данных. Сохраните HTTP-статус и тело ответа.
3. Рассчитайте показатели по таблице. Включите время проверки пустого тома в интервал восстановления.

| Показатель | Как определить | Учебный критерий |
| --- | --- | --- |
| Фактическое время восстановления | `t_recovered − t_failure` | RTO ≤ 10 минут |
| Возраст восстановленной копии на момент сбоя | `t_failure − t_backup` | RPO ≤ 5 минут |
| Потерянные записи | Сравните списки до сбоя и после восстановления | Укажите идентификаторы отсутствующих записей |

Укажите, уложились ли вы в заданные пределы RTO и RPO. Объясните, как момент создания копии повлиял на результат проверки RPO. Если какой-либо предел превышен, приведите фактический результат и объясните причину.

### Задание 6. Подготовьте отчёт

Сдайте индивидуальный отчёт **на английском языке** объёмом около 2–3 страниц. Имя файла — `CC_PZ3_Surname_Group.pdf`. Укажите имя, группу, дату, гостевую ОС и версию Docker. Укажите команду сборки, идентификатор и архитектуру собранного образа. Приведите использованные команды и схему, на которой видны API, том Docker и расположение резервной копии. Заполните таблицу фактическими результатами. Для каждой строки укажите, где приведён соответствующий вывод команды или ответ API.

| Контрольная точка | HTTP-статус | Идентификаторы записей в ответе | Подтверждение |
| --- | --- | --- | --- |
| До пересоздания контейнера | | | |
| После пересоздания контейнера | | | |
| После добавления записи C | | | |
| После запуска с пустым томом | | | |

Включите в отчёт три отметки времени, расчёты и результаты проверки резервной копии. В кратком выводе объясните, почему записи A и B сохранились при пересоздании контейнера, почему запись C отсутствует после восстановления и что произойдёт с резервной копией при потере диска ВМ.

По окончании работы остановите стенд. Сохраните отчёт, материалы проверки и резервную копию до выставления оценки.
